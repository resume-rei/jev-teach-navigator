# Jev Teach Navigator

更新: 2026-10-18（GitHub掲載用の案内を追加）

**改良を担当するAIへ:** [AI_REVIEW_PROMPT.md](AI_REVIEW_PROMPT.md) に、利用者の目的、読むコード、改良の優先順、維持する条件をまとめています。

Windows全体を対象に、人に教えるように「何をするか」を記録し、現在の画面から対象を探し直してEnterごとに操作を進めるデスクトップアプリを目指します。デスクトップ、エクスプローラー、複数アプリ間の移動もタスクに含めます。ブラウザー拡張は前提にしません。

**Windowsネイティブ版で「別アプリへ切替 → 現在の対象へ赤矢印 → Enterで1操作 → 結果確認 → 次の矢印を自動表示」が動きます。** 2つの練習アプリを別プロセスとして起動し、資料棚 → 申請アプリ → 資料棚の5手順・8操作を実機で通しました。ブラウザーや拡張機能は不要です。

今回は3段階のうち第1段階、Windowsの連続案内基盤まで実装しています。操作先は、この起動中に開いた専用練習アプリに限定しています。任意の業務アプリ、デスクトップのアイコン、教えたスキルからの実行、Jevの画像認識は次段階です。既存のWeb版は教示・保存の別試作として残しています。

このリポジトリにはソース、テスト、現行設計資料を収録しています。ローカルの学習記録、画像、実行ログ、認証情報、チャット管理情報を含む初期引継ぎ資料、ビルド済みexeは含めません。

## Windows版を起動する

clone後、リポジトリのフォルダーで次を実行します。初回は `windows/bin/JevTeachWindows.exe` が生成され、以降はexeを直接開くこともできます。Windows x64 / .NET Framework 4.xを使用し、追加パッケージやAPIキーは不要です。

```powershell
.\start-windows.ps1
```

1. 「練習アプリを開いて案内を開始」を押す。
2. 提示された操作と赤矢印を確認してEnter。アプリ切替も、ボタン押下も、それぞれ1回のEnterで承認する。
3. 結果確認後に次の矢印が自動で出るので、Enterで続ける。合計5手順・8操作で完了する。
4. Escで一時停止。「案内を再開」で現在画面から探し直す。「案内を終了」で受付を止める。

長押しや処理中の連打は、次の操作への承認として貯めません。案内対象外のアプリへ移ると待機し、戻ると再観察します。入力欄内・IME変換中・修飾キー付きのEnterは案内承認にしません。日本語IMEの実機検証は未実施です。

練習画面の「配置を変える」「同名を増やす」「対象を隠す」「遷移しない」「1秒遅らせる」で画面変化を試せます。同名・不在は保留、結果不明は停止し、自動再実行しません。結果不明の間はEnterも保留し、Escまたは「案内を終了」で受付を終了できます。過去座標を保存せず、その時のUIAの名前・役割・文脈・要素・矩形から特定します。

案内パネルの「Enter → 次の提示」は承認受付からの経過時間です。`data/windows/runs/` に操作数・結果・時間だけを保存します。画面録画、音声、入力内容、キー入力の履歴は保存しません。API通信は0回です。閉じると、このセッションの練習アプリだけを終了します。

確認画像と計測ログはローカルに保管し、GitHubには含めていません。検証履歴と未確認範囲は [HANDOFF.md](HANDOFF.md) を参照してください。

## Webの教示・保存試作を起動する

必要: Node.js 22以上。npm依存はありません。APIキーも不要です。

```powershell
.\start.ps1
# または npm start
```

表示された [ローカル画面](http://127.0.0.1:4327) を開きます。停止は端末で `Ctrl+C`。既定ポートが使用中なら `./start.ps1 -Port 4328`。他のサービスは停止しません。

## 最初の一周

1. 「教える」で「教えるモードを開始」。状態が「記録中」になります。
2. 架空画面の「申請する」を**右クリック**。「これは申請ボタン」と説明欄に書き、「説明を記録」。この右クリックでは画面は進みません。
3. 同じボタンを左クリック。件名と申請理由を架空の内容で入力します。入力欄を右クリックして「ここは毎回変わる」と説明することもできます。
4. 「確認画面へ」を左クリック。「ここが確認画面」と記録します。画面説明のためのクリックは不要です。
5. 「申請を送信」を左クリック。完了画面を説明し、「この画面を手順の完了条件にする」をチェックして説明を記録。
6. 「記録を停止して保存」。手順がローカルへ自動保存されます。
7. 「一覧へ戻す」→「案内してもらう」。例:「備品を申請したい」でスキルを探します。
8. 「現在の画面から提案」で赤矢印が出ます。**フォーカスが当たった承認エリアでEnter**を押すと、その1操作だけを実行します。
9. 毎回「現在の画面から提案」→内容確認→Enter。入力案も全文を表示し、送信とは別の操作として承認します。

入力案は「入力案を確認・修正する」から変更できます。mockは定型案と語句一致を使います。Jev/Lunaが実際に推論した結果ではありません。

右ドラッグは参考領域を記録します。その矩形は実行位置に使いません。キーボードで対象を指すには、対象へTab移動してShift+F10。Escは指定・提案の取消です。Enterの長押し・IME確定・入力欄内のEnterは承認に使いません。

## 保存と修正

「保存したスキル」→「閲覧・修正」でJSONを編集できます。名前、目的、依頼例、対象の意味、手順、完了条件を確認できます。参照関係や前後画面が不正な変更は保存を拒否します。

- `data/skills/<id>/v1.json`, `v2.json`, … に追記。古い版は保持。
- 現在版を元に保存し、他の画面で先に更新された場合は競合を通知。
- 完了条件不足、条件文の未解決、クリック後の変化が未観察なら「未完成」。案内候補にはしません。
- 入力欄の実値・画像・音声・認証情報用フィールドは記録に含めません。
- 自由文に認証情報らしい文字列があると保存を拒否します。ただし任意の秘密を完全に検出する機能ではありません。試作には架空データだけを使ってください。
- 記録は開始後だけ。タブ非表示で教示を停止します。停止後の未保存記録は保存ボタンで保存できます。
- `data/` はGit対象外です。クラッシュ前の未保存セッションは復元対象ではありません。

## テスト

```powershell
npm test
npm run check
.\windows\build.ps1 -SelfTest
```

自動テストはローカルの架空データだけを使います。実API呼出、マイク、実アプリへの入力は行いません。HTTPテストと保存テストのデータはOSの一時フォルダー `jev-test-*` / `jev-http-*` に保存されます。

## Windows教示の検証アプリを開く

```powershell
.\start-windows.ps1 -TeachingLab
```

.NET Framework 4.xのコンパイラー・UIAutomation・System.Speechが必要です。追加ダウンロードはしません。

まず「架空のWindows画面を開く」を使います。教示開始後の右クリックでUIA対象を囲み、右ドラッグで領域を指定できます。左クリックは通し、UIA画面の変化を観察します。画面全体の説明も記録可能です。停止時にフックとマイクを解除します。保存先は `data/windows/` で、ブラウザーのスキルとは別形式です。

音声入力は明示的にボタンを押したときだけ。日本語のローカル認識エンジンがない場合は文字入力へ戻ります。音声ファイルは保存せず、認識された説明を利用者が確認して記録します。

この教示ラボの旧案内部分はdry-runが初期状態です。候補を選び再特定して矢印を表示し、承認欄のEnterで確認します。連続案内は通常起動のWindows版で試します。Windows教示の保存スキル・入力案・自然文選択と、連続案内との接続はまだ行っていません。

## 実APIを確認する場合

通常の画面は常にmockです。APIキーをブラウザーや記録へ渡しません。単発検証CLIは、**送信内容のプレビューが既定**です。

```powershell
# 課金呼出なし
node scripts/api-probe.mjs route --request '備品を申請したい'
node scripts/api-probe.mjs box --image 'C:\path\fictional-screen.png' --target '備品申請の申請するボタン'
# 生成はGENERATOR_MODELに、確認済みのAPIモデルIDを設定してから
node scripts/api-probe.mjs compile --skill 'C:\path\skill.json'
node scripts/api-probe.mjs draft --request '備品を申請したい' --label '申請理由'
```

実送信する場合だけ、端末の環境変数 `TYPESAFE_API_KEY` または `OPENAI_API_KEY` を設定し、同じコマンドへ `--send` を追加します。CLIが表示する接続先・モデル・データ・1回の呼出を確認し、対話入力で承認します。料金・利用枠は別途確認してください。1回という回数制限は金額上限ではありません。エラー時も自動再試行しません。

`--output` は新規ファイルにのみ保存します。生成結果は自動実行しません。Lunaの製品表示名から公開APIモデルIDを推測した既定値は設けていません。
