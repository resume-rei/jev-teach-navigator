# Jev Teach Navigator

更新: 2026-10-18

Windows上で人が操作の意味を教え、保存したスキルを選び、実行時の画面から対象を探し直して案内するデスクトップアプリです。**明示的なアプリ登録 → 構造化した教示 → 版を残す保存・編集 → スキル選択 → 今回の入力指定 → Enterごとの連続案内**をネイティブ版へ接続しました。ブラウザー拡張やAPIキーは不要です。

現在の一般アプリ経路は、利用者が登録したウィンドウ内でUI Automation（UIA）の `InvokePattern` / `ValuePattern`を提供する対象に限ります。アプリ切替も独立した1操作として提示します。UIAで対象を一意に確認できなければ保留し、過去座標の再生や画像APIへの自動切替はしません。

**今回の変更はLinux上の自動テストとWindows向けクロスコンパイルまで確認しました。新しい教示・保存・一般アプリ案内、実UIA、物理Enter、IMEのWindows実機確認は未実施です。** 以前の専用練習アプリでの実機成功は、今回の一般アプリ対応の成功証拠とは区別しています。

最終目標にはデスクトップ、エクスプローラー、ダイアログ、アプリ起動、スクロールなどを含みます。その全体対応、キーボードだけによる教示、生成モデルによる教示整理、画像での対象再特定は未完成です。

改良を担当するAIは、最初に [AI_REVIEW_PROMPT.md](AI_REVIEW_PROMPT.md)、本書、[DESIGN.md](DESIGN.md)、[HANDOFF.md](HANDOFF.md)を読み、実装と照合してください。公式仕様と参考コードは [docs/SOURCES.md](docs/SOURCES.md)にまとめています。

## Windows版を起動する

Windows x64 / .NET Framework 4.xを使用します。リポジトリのフォルダーで実行してください。初回に `windows/bin/JevTeachWindows.exe`をビルドします。追加パッケージやAPIキーは不要です。

```powershell
./start-windows.ps1
```

### まず練習アプリで案内を確認する

「練習アプリを開いて案内を開始」で、別プロセスの資料棚と申請アプリを起動します。操作内容と赤矢印を見てEnterを押すと、1操作だけ実行し、結果確認後に次の提案を自動表示します。用意した手順は5手順・3回の切替を合わせた8操作です。

「配置を変える」「同名を増やす」「対象を隠す」「遷移しない」「1秒遅らせる」で再特定と保留を試せます。Escで一時停止、「案内を再開」で現在画面から再観察、「案内を終了」で受付を止めます。結果不明の操作は再送しません。

### 一般アプリを教え、保存して案内する

最初のWindows実機確認には、変更して差し支えない架空データを使ってください。具体的な確認項目は [docs/WINDOWS_CHECKS.md](docs/WINDOWS_CHECKS.md)にあります。この一覧は今回すべて未実施です。

1. 案内パネルの「アプリ登録・教える・保存スキル」を開きます。
2. 「ウィンドウ一覧を更新」で操作するウィンドウを選び、`editor`などのアプリ名を付けて「選んだウィンドウだけを登録」。複数アプリを使う場合は各ウィンドウを登録します。アプリ名は次回も同じものを使います。
3. 「教えるモードを開始」。登録アプリの対象を右クリックして強調します。この右クリックでは実行しません。右ドラッグは参考領域の表示だけで、実行座標には保存しません。
4. 操作の意味、`invoke` / `set-value`、開始画面の目印を確認します。目印は現在のUIA候補から選ぶため、画面説明用の追加クリックは不要です。入力ならパラメータ名を付け、実際の文章は保存しません。
5. 普段どおり左クリックして操作します。入力教示も欄を左クリックしてから入力します。現在はこの操作観察を必要とし、キーボードだけの教示には対応していません。
6. 結果が表示される登録アプリを選び、「普段どおり操作した後、現在の結果候補を観察」。`invoke`では操作前から見えていた目印を成功扱いせず、新しく現れた一意な結果を選びます。入力の実行時の成功条件は、今回承認した全文との一致です。
7. 「意味と結果を確認して1手順を追加」を繰り返し、「記録を停止してスキルの下書きを作る」。未解決の条件を実行可能と推測しません。
8. JSONを閲覧・修正し、全手順・入力パラメータ・最後の結果を確認して「新しい版として保存」。確認不足の下書きは案内できません。旧版の閲覧・新しい版への復元も可能です。
9. 一覧、または保存した名前・依頼例を使う依頼文からスキルを選びます。語句一致による選択で、Jevや生成モデルの推論ではありません。開始前に表示内容と現在の保存版が一致するかを再確認します。
10. 「選択した保存スキルで案内を始める」。今回入力する全文を別欄で指定します。欄を消去する場合だけ「空文字で欄を消去する」を明示選択します。案内パネルでも入力全文を確認でき、入力と送信は別々のEnterで承認します。

登録はこのナビ起動中だけ有効です。アプリ再起動・ウィンドウの作り直し後は再登録してください。新しく開くダイアログを同じプロセスという理由で追従せず、必要なら別の登録対象にします。登録した一般アプリはナビ終了時も閉じません。ナビ自身が起動した練習アプリだけが終了処理の対象です。

## Enterと結果確認

一般アプリへの案内では、ナビの非編集承認欄「内容を確認して、ここでEnter」にフォーカスがある場合だけ承認します。入力欄や対象アプリでのEnterは承認にしません。次の表示が確定した後の新しい物理Enter押下を必要とし、長押し、処理中の連打、注入イベントを次の操作へ持ち越さないガードを実装しています。

実行直前に現在画面、前面、登録ウィンドウの同一性、対象、矩形、入力全文、提案の期限を再確認します。移動・消失・重複・人の介入などで前提が変われば失効・保留します。処理中の取消後に操作が実行された可能性を否定できない場合も、結果不明として自動再実行しません。一般アプリでのフォーカス・IME・物理キーフックの実際の振る舞いは実機確認が必要です。

## 保存先と形式

| 保存先 | 内容 |
| --- | --- |
| `data/windows/skills/<id>/vN.json` | ネイティブ `schemaVersion: 2` / `windows-uia`。意味、アプリ名、UIA対象の特徴、事前条件、結果、入力パラメータ名。版は追記 |
| `data/windows/runs/` | 操作数、状態、所要時間。入力全文、画像、音声、キー履歴は保存しない |
| `data/skills/<id>/vN.json` | 既存Web試作のschemaVersion 1。ネイティブ版とは別の保存先 |
| 旧教示ラボの `data/windows/` | 実行不能の教示証拠。取り込みは要確認の下書きになる |

過去座標、HWND、PID、RuntimeId、入力した実値をネイティブスキルへ保存しません。編集要素や機密欄のUIA情報を意味記録へ混ぜない制限も設けていますが、自由文の任意の秘密を完全に検出する機能ではありません。説明文へ秘密を書かないでください。

同じ版への上書き、壊れた最新版の黙った初期化、未知フィールドの黙認は拒否します。旧Webスキルや旧教示証拠は元ファイルを保持し、再確認が必要な下書きとして取り込みます。WebのDOM条件がそのままWindowsの操作許可になることはありません。

`data/`、確認画像、認証情報、ビルド済みexeはGitHubへ含めません。未保存の教示は終了・クラッシュ後の復元対象ではありません。

## Web試作と旧Windows教示ラボ

既存Web版は、架空の申請画面で教示・版保存・DOMの意味による再特定を試す別経路です。Node.js 22以上、npm依存なし。`./start.ps1` または `npm start`で起動し、[ローカル画面](http://127.0.0.1:4327)を開きます。停止は端末で`Ctrl+C`、ポート変更は `./start.ps1 -Port 4328`です。

Webでは「教える」から右クリック対象指定・文字説明・普段の操作・完了画面の確認を記録し、「記録を停止して保存」。保存後に「案内してもらう」から選択します。案内は各回「現在の画面から提案」→承認欄のEnterで、ネイティブの自動次提案とは異なります。入力案はmockの定型案を確認・修正します。右ドラッグは参考領域、Tab移動後のShift+F10は対象指定、Escは取消です。

`./start-windows.ps1 -TeachingLab`は旧Windows教示ラボです。ローカル音声を明示開始する別の試作が残っていますが、通常の登録・教示・保存経路ではマイクを使いません。旧ラボの案内は既定dry-runで、保存する教示証拠は直接実行できません。今回マイクは検証していません。

以前の背景プレビューを起動した環境だけで、そのプロセスを止めるには `./stop-preview.ps1`を使えます。clone先でプレビューが起動中という意味ではありません。

## 実APIの検証境界

通常のネイティブ案内はUIAだけ、Webサーバーはmock固定です。Jevと生成モデルのアダプターは単発検証CLIに分離しており、新しいWindows schemaVersion 2へは未接続です。既定は送信内容のプレビューです。

```powershell
# 課金呼出なし。routeは既存Webスキルを候補にする
node scripts/api-probe.mjs route --request '備品を申請したい'
node scripts/api-probe.mjs box --image 'C:/path/fictional-screen.png' --target '備品申請の申請するボタン'
# compileはWeb schemaVersion 1。生成用にはGENERATOR_MODELの明示設定が必要
node scripts/api-probe.mjs compile --skill 'C:/path/skill.json'
node scripts/api-probe.mjs draft --request '備品を申請したい' --label '申請理由'
```

**実API・課金・実データの外部送信が必要になった時点で利用者へ確認してください。** 承認後だけ環境変数 `TYPESAFE_API_KEY` / `OPENAI_API_KEY`を設定して`--send`を使います。CLIは接続先、モデル、送信本文に結び付いた1回限りの対話承認を要求します。キーをチャットやGitへ保存しません。1回の制限は金額上限ではなく、エラー時の自動再試行もありません。`--output`は新規ファイルだけを作成し、生成結果は自動実行しません。

Jev画像の公式最小辺は**280px**です。Boxは1対象で、不在でも矩形が返り得るため、存在と一意性を確認してから使います。Choice結果に依存するBoxは別リクエストです。現行公式制限、ローカル検査の限界、模擬契約テストは [docs/JEV_CONTRACT_REVIEW.md](docs/JEV_CONTRACT_REVIEW.md)を参照してください。実認識の品質や費用は未検証です。
